# 기술 교육 이수 현황 시스템 PRD

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 문서명 | 기술 교육 이수 현황 시스템 제품 요구사항 정의서(PRD) |
| 버전 | 1.0 |
| 작성일 | 2026-09-17 |
| 제품 단계 | 기존 샘플 시스템 전면 개편을 위한 1차 제품 정의 |
| 주요 독자 | 인사 담당자, 부서장·팀장, 교육 운영자·강사, 시스템 관리자, 개발·QA 담당자 |

이 문서는 현재 샘플로 구현된 교육 이수 현황 대시보드를 실제 운영 가능한 사내 시스템으로 개편하기 위한 제품 목표, 업무 규칙, 기능 범위, 권한, 데이터 구조 및 인수 기준을 정의한다.

---

## 2. 배경과 문제 정의

직원의 기술 교육 수료 이력, 현재 소속, 과거 부서 이력과 교육 대상 여부가 여러 파일 또는 담당자의 경험에 분산되어 있으면 다음 문제가 발생한다.

- 부서별·과정별 수료 현황을 파악하는 데 반복적인 수작업이 필요하다.
- 수료율의 기준이 불명확해 담당자마다 다른 결과를 산출할 수 있다.
- 신규 입사, 부서 이동, 퇴사에 따라 교육 대상자가 달라져도 즉시 반영하기 어렵다.
- 강사가 제공한 차수별 수료 명단을 기존 직원 정보와 대조하고 반영하는 과정에서 누락·중복·오입력이 발생할 수 있다.
- 직원 개인의 교육 및 근무 이력을 한 번에 확인하기 어렵다.
- 부서장과 인사 담당자가 육성 계획이나 업무 배치 후보를 찾을 때 일관된 근거를 확보하기 어렵다.

본 제품은 직원, 조직, 교육 과정, 교육 차수, 교육 대상 조건과 수료 이력을 하나의 기준으로 관리하여 이러한 문제를 해결한다.

## 3. 제품 비전과 목표

### 3.1 제품 비전

회사의 기술 역량 강화 활동을 신뢰할 수 있는 데이터로 보여주고, 직원의 경력 개발과 조직의 인재 육성 의사결정을 지원하는 단일 교육 이력 플랫폼을 만든다.

### 3.2 1차 목표

1. 재직자 기준의 정확한 교육 대상자, 수료자, 미수료자와 수료율을 제공한다.
2. 직원의 입사, 퇴사, 현재 소속과 과거 부서 근무 이력을 일관되게 관리한다.
3. 교육 과정과 실제 시행 차수를 분리하여 차수별 수료 명단과 과정 누적 수료 현황을 모두 제공한다.
4. 강사가 제공한 CSV 수료 명단을 안전하게 검증하고 일괄 반영한다.
5. 부서, 교육 과정, 직원 관점의 현황을 빠르게 탐색하고 내보낼 수 있게 한다.
6. 사용자 역할과 담당 범위에 맞춰 필요한 정보만 조회·수정할 수 있게 한다.
7. 교육 과정에 역량 태그를 부여하여 향후 경력 관리와 인재 검색 기능의 기반을 마련한다.

### 3.3 비목표

다음 항목은 1차 출시 범위에 포함하지 않는다.

- 교육 신청, 승인, 대기자 및 정원 관리
- 실시간 출결, 온라인 학습 콘텐츠 제공 및 LMS 연동
- 교육비, 강사비, 예산 및 정산 관리
- 메일·메신저 자동 발송
- 성과평가 또는 인사고과 기능
- 교육 수료만으로 개인의 숙련도를 판정하는 기능
- 알고리즘에 의한 자동 인재 추천 또는 자동 업무 배치
- 자격증과 수상 이력의 본격적인 관리

자격증, 숙련도 평가, 직무별 필수 역량, 추천 배치 기능은 1차 데이터가 안정적으로 축적된 후 별도 단계에서 확장한다.

## 4. 사용자와 사용 목적

### 4.1 사용자 유형

| 사용자 | 주요 목적 |
|---|---|
| 시스템 관리자 | 사용자 계정, 권한, 기준정보, 시스템 설정 및 전체 감사 이력 관리 |
| 인사 담당자 | 직원·조직 정보 관리, 전사 교육 현황 분석, 육성 및 인력 선발 지원 |
| 부서장·팀장 | 관할 조직의 수료·미수료 현황 파악, 팀원 경력 개발 및 업무 배치 참고 |
| 교육 운영자·강사 | 담당 과정과 차수 관리, 수료 명단 업로드, 수료율 및 미수료 현황 확인 |
| 일반 직원 | 본인의 교육 수료 이력, 획득한 역량 태그 및 근무 부서 이력 확인 |
| 임원 | 전사 및 조직별 역량 강화 활동 수준과 회사 방향성의 정합성 확인 |

### 4.2 핵심 사용자 시나리오

- 팀장은 자신의 팀에서 특정 과정의 수료자와 미수료자를 즉시 비교한다.
- 인사 담당자는 특정 기술 또는 교육을 이수한 재직자를 검색해 업무 후보군을 만든다.
- 강사는 교육 종료 후 차수별 CSV를 업로드하고 오류 행을 수정한 뒤 수료 결과를 반영한다.
- 교육 운영자는 과정별 대상 조건에 따라 다음 차수 후보자를 산정하고 명단을 내려받는다.
- 직원은 본인의 교육 및 부서 이동 이력을 시간순으로 확인한다.
- 임원은 조직별·과정별 수료 현황과 추이를 통해 역량 강화 활동을 점검한다.

## 5. 제품 원칙

1. **수료와 숙련도를 구분한다.** 수료 이력은 교육 완료 사실이며 실제 업무 숙련도를 보증하지 않는다.
2. **과정과 차수를 구분한다.** 과정은 반복 운영되는 교육의 정의이고, 차수는 특정 기간에 실제로 진행한 교육이다.
3. **현재 상태와 이력을 함께 보존한다.** 부서 이동과 퇴사는 기존 수료 및 근무 기록을 삭제하지 않는다.
4. **집계 기준을 설명 가능하게 한다.** 모든 수료율 화면에서 기준일, 분모, 분자와 제외 조건을 확인할 수 있어야 한다.
5. **대량 반영 전 검증한다.** CSV 데이터는 즉시 저장하지 않고 사전 검증과 사용자 확인을 거친다.
6. **최소 권한을 적용한다.** 사용자는 역할과 담당 범위에 필요한 정보만 조회·수정한다.
7. **원본 변경을 추적한다.** 직원, 대상 조건, 수료 이력의 생성·변경·취소는 감사 로그에 남긴다.

## 6. 핵심 용어와 업무 규칙

### 6.1 핵심 용어

| 용어 | 정의 |
|---|---|
| 교육 과정 | 반복 시행할 수 있는 교육의 기준 정의. 과정명, 설명, 상태, 역량 태그, 대상 조건 등을 가진다. |
| 교육 차수 | 특정 과정이 실제로 시행되는 단위. 차수명, 교육 기간, 강사, 상태를 가진다. |
| 대상 조건 | 부서, 직급, 직무, 입사일 등으로 특정 과정의 수강 필요 대상을 판정하는 규칙이다. |
| 과정 대상자 | 기준일 현재 재직자 중 과정의 대상 조건을 충족하는 직원이다. |
| 차수 참여자 | 특정 교육 차수에 배정되거나 실제 참여한 직원이다. |
| 수료 이력 | 직원이 특정 차수에서 해당 과정을 수료했다는 확정 기록이다. |
| 미수료자 | 과정 대상자이지만 해당 과정의 유효한 수료 이력이 없는 직원이다. |
| 역량 태그 | 과정이 다루는 직무, 기술, 장비 또는 제품 영역을 나타내는 검색용 분류다. |

### 6.2 재직 상태

- 직원 상태는 `재직`, `휴직`, `퇴사`로 관리한다.
- 신규 입사자는 별도 영구 상태로 두지 않고 입사일과 등록일로 판정한다.
- 기본적으로 퇴사자는 현재 대상자와 수료율 집계에서 제외한다.
- 퇴사자의 직원 정보, 부서 이력 및 수료 이력은 보존한다.
- 휴직자는 기본 집계에 포함하되 화면 필터로 제외할 수 있다. 회사 정책상 휴직자를 대상에서 제외해야 하는 과정은 대상 조건에서 예외를 설정한다.

### 6.3 부서 이력

- 직원은 기준일마다 하나의 유효한 소속 부서만 가진다.
- 부서 이력의 시작일과 종료일은 서로 겹칠 수 없다.
- 현재 부서는 종료일이 없는 최신 부서 이력으로 계산한다.
- 부서 변경 시 기존 이력의 종료일을 이동 전일로 확정하고 새 이력을 생성한다.
- 과거 차수의 부서별 통계는 교육 종료일 당시 소속을 기준으로 조회할 수 있고, 현재 조직 육성 현황은 현재 소속을 기준으로 조회한다.

### 6.4 과정 수료 판정과 수료율

- 과정 수료자는 해당 과정의 어느 차수에서든 취소되지 않은 수료 이력이 있는 직원이다.
- 동일 과정을 여러 차수에서 수료해도 과정 누적 수료자 수는 직원 1명으로 계산한다.
- 기본 과정 수료율은 다음과 같이 계산한다.

> 과정 수료율 = 기준일 현재 과정 대상자 중 수료 이력이 있는 재직자 수 ÷ 기준일 현재 과정 대상 재직자 수 × 100

- 기본 미수료자는 `기준일 현재 과정 대상 재직자 - 과정 수료자`로 계산한다.
- 과정 대상 조건이 변경되면 현재 수료율은 새 조건으로 재계산하며, 변경 전 결과는 감사 이력과 기간별 스냅샷으로 추적한다.
- 분모가 0명인 경우 수료율은 0%가 아니라 `대상자 없음`으로 표시한다.
- 차수 수료율은 다음과 같이 별도로 계산한다.

> 차수 수료율 = 해당 차수 참여자 중 수료자 수 ÷ 해당 차수 참여자 수 × 100

- 차수 참여자가 0명인 경우 차수 수료율은 `참여자 없음`으로 표시한다.
- 수료의 유효기간은 1차에서는 무기한을 기본값으로 한다. 과정에 유효기간이 설정된 경우 만료일 이후에는 현재 수료 판정에서 제외하되 과거 수료 이력은 보존한다.

### 6.5 집계 기준일

- 모든 현황 화면의 기본 기준일은 조회 당일이다.
- 권한이 있는 사용자는 과거 기준일을 선택해 당시 조직과 대상 조건에 따른 현황을 조회할 수 있다.
- 내보내기 파일에는 조회 기준일과 적용된 필터를 포함한다.

## 8. 기능 요구사항

요구사항 우선순위는 `필수`, `권장`, `후속`으로 구분한다. 1차 출시 인수 범위는 필수 요구사항이다.

### 8.1 직원 및 조직 관리

| ID | 우선순위 | 요구사항 |
|---|---|---|
| EMP-01 | 필수 | HR 또는 관리자는 사번, 이름, 이메일, 입사일, 직급, 직무, 재직 상태를 입력하여 직원을 등록할 수 있다. |
| EMP-02 | 필수 | 사번은 퇴사자를 포함해 시스템 전체에서 중복될 수 없다. |
| EMP-03 | 필수 | 사용자는 이름, 사번, 부서, 직급, 직무, 상태로 직원 목록을 검색·필터링할 수 있다. |
| EMP-04 | 필수 | HR 또는 관리자는 퇴사일과 사유를 입력하여 직원을 비활성화할 수 있다. 퇴사 처리 시 기존 이력은 삭제되지 않는다. |
| EMP-05 | 필수 | HR 또는 관리자는 복직 또는 오입력 정정을 위해 직원 상태를 변경할 수 있고 변경 이력이 기록된다. |
| EMP-06 | 필수 | HR 또는 관리자는 부서 이동의 시작일을 입력해 소속을 변경할 수 있다. 시스템은 기존 이력의 종료일을 자동 설정한다. |
| EMP-07 | 필수 | 시스템은 직원 상세 화면에 현재 정보, 교육 수료 이력, 역량 태그, 부서 근무 이력을 시간순으로 표시한다. |
| EMP-08 | 권장 | HR은 표준 양식의 CSV로 직원 신규 등록 및 기본정보 변경을 일괄 처리할 수 있다. |
| EMP-09 | 필수 | 직원 삭제 기능은 제공하지 않는다. 잘못 생성된 직원은 관리자만 병합 또는 비활성 처리할 수 있다. |

### 8.2 교육 과정 및 대상 조건 관리

| ID | 우선순위 | 요구사항 |
|---|---|---|
| CRS-01 | 필수 | 교육 운영자는 과정명, 과정 코드, 설명, 운영 상태, 유효기간, 담당자를 등록·수정할 수 있다. |
| CRS-02 | 필수 | 과정 코드는 시스템 전체에서 중복될 수 없다. |
| CRS-03 | 필수 | 과정에 하나 이상의 역량 태그를 연결할 수 있다. |
| CRS-04 | 필수 | 대상 조건은 부서, 직급, 직무, 재직 상태, 입사일 범위를 조합하여 설정할 수 있다. |
| CRS-05 | 필수 | 서로 다른 조건 그룹은 OR, 한 조건 그룹 안의 항목은 AND로 판정한다. |
| CRS-06 | 필수 | 특정 직원을 대상에 추가하거나 제외하는 예외를 설정할 수 있으며, 예외 사유를 기록해야 한다. |
| CRS-07 | 필수 | 조건 저장 전 예상 대상자 수와 명단을 미리 확인할 수 있다. |
| CRS-08 | 필수 | 대상 조건 변경 시 영향받는 인원과 수료율 변화를 미리 보여주고 확인 후 반영한다. |
| CRS-09 | 필수 | 과정은 삭제하지 않고 `운영 중`, `중단`, `종료` 상태로 관리한다. 종료 과정의 과거 이력은 조회할 수 있다. |
| CRS-10 | 권장 | 관리자는 과정 간 선행 관계를 참고 정보로 설정할 수 있다. 1차에서는 자동 수강 제한에 사용하지 않는다. |

### 8.3 교육 차수 관리

| ID | 우선순위 | 요구사항 |
|---|---|---|
| SES-01 | 필수 | 교육 운영자는 과정에 차수명, 시작일, 종료일, 강사, 장소 또는 진행 방식을 입력하여 차수를 개설할 수 있다. |
| SES-02 | 필수 | 차수 상태는 `예정`, `진행 중`, `결과 입력`, `마감`, `취소`로 관리한다. |
| SES-03 | 필수 | 예정 차수에는 과정 미수료자 중 대상 조건을 충족하는 직원을 후보자로 불러올 수 있다. |
| SES-04 | 필수 | 교육 운영자는 후보자 중 실제 참여자를 선택하거나 CSV로 참여자 명단을 등록할 수 있다. |
| SES-05 | 필수 | 차수 상세에서 참여자, 수료자, 미수료자, 수료율을 확인할 수 있다. |
| SES-06 | 필수 | 차수 마감 후 결과 변경은 관리자 또는 HR만 수행할 수 있고 변경 사유가 필요하다. |
| SES-07 | 필수 | 차수가 취소되어도 기록은 보존되며 과정 수료율과 차수 실적 집계에서는 제외한다. |

### 8.4 수료 이력 및 CSV 업로드

| ID | 우선순위 | 요구사항 |
|---|---|---|
| CMP-01 | 필수 | 강사 또는 교육 운영자는 담당 차수의 수료 결과 CSV를 업로드할 수 있다. |
| CMP-02 | 필수 | 필수 열은 `사번`, `수료일`, `수료여부`이다. 선택 열은 `이름`, `점수`, `비고`이다. |
| CMP-03 | 필수 | 업로드 시 사용자는 파일 열을 시스템 필드에 매핑하고 미리보기로 확인할 수 있다. |
| CMP-04 | 필수 | 시스템은 필수값 누락, 잘못된 날짜, 존재하지 않는 사번, 파일 내 중복, 이미 등록된 수료, 차수 기간 밖 수료일, 사번·이름 불일치를 검증한다. |
| CMP-05 | 필수 | 검증 결과를 정상, 경고, 오류로 구분한다. 오류 행은 반영하지 않으며 경고 행은 사용자가 확인한 경우에만 반영한다. |
| CMP-06 | 필수 | 사용자는 최종 반영 전에 신규 수료, 기존 값 유지, 기존 값 변경, 제외 건수를 확인할 수 있다. |
| CMP-07 | 필수 | 한 번의 업로드는 전체가 성공하거나 전체가 취소되는 원자적 처리를 기본으로 한다. 오류 행을 제외하고 반영하려면 사용자가 오류 행 제외를 명시적으로 선택해야 한다. |
| CMP-08 | 필수 | 업로드 결과에는 처리자, 처리 시각, 원본 파일명, 파일 해시, 차수, 성공·제외·오류 건수를 기록한다. |
| CMP-09 | 필수 | 동일 직원이 동일 과정의 다른 차수에서 다시 수료하면 차수별 이력은 모두 보존하되 과정 누적 수료자는 1명으로 계산한다. |
| CMP-10 | 필수 | 잘못된 수료 이력은 삭제 대신 취소 처리하고 사유와 처리자를 기록한다. |
| CMP-11 | 권장 | 사용자는 검증 오류 목록을 CSV로 내려받아 원본을 수정할 수 있다. |

| MetricSnapshot | 기준일, 과정, 부서, 대상자 수, 수료자 수 | 과거 지표 재현 및 추이 분석 |

개인정보 최소화를 위해 생년월일은 교육 이수 관리에 필요하지 않으므로 1차 기본 데이터에서 제외한다. 업무상 추가 식별이 필요하면 사번을 사용한다.

## 11. 주요 업무 흐름

### 11.1 신규 입사자 등록

1. HR이 직원의 필수 정보를 입력한다.
2. 시스템이 사번과 이메일 중복을 검사한다.
3. 최초 부서 이력을 입사일 기준으로 생성한다.
4. 대상 조건 엔진이 신규 직원에게 해당하는 과정을 계산한다.
5. 직원 상세와 관련 과정의 미수료자 명단에 결과를 반영한다.

### 11.2 부서 이동

1. HR이 새 부서와 이동 시작일을 입력한다.
2. 시스템이 이력 기간 중복과 미래·과거 날짜의 유효성을 검사한다.
3. 기존 부서 이력을 이동 전일로 종료하고 새 이력을 생성한다.
4. 현재 기준 과정 대상자를 다시 계산한다.
5. 과거 차수와 수료 이력은 변경하지 않는다.

### 11.3 퇴사 처리

1. HR이 퇴사일과 사유를 입력한다.
2. 직원 상태를 퇴사로 변경하고 현재 부서 이력을 종료한다.
3. 현재 대상자와 수료율 분모에서 해당 직원을 제외한다.
4. 개인·교육·근무 이력은 보존한다.

### 11.4 과정 및 차수 개설

1. 교육 운영자가 과정 또는 기존 과정을 선택한다.
2. 대상 조건과 역량 태그를 설정하고 예상 대상자를 확인한다.
3. 차수 일정과 담당 강사를 등록한다.
4. 과정 미수료자 후보에서 참여자를 선택한다.
5. 교육 진행 후 차수를 결과 입력 상태로 전환한다.

### 11.5 CSV 수료 결과 반영

1. 사용자가 대상 차수를 선택하고 CSV를 업로드한다.
2. 파일 형식과 열 매핑을 확인한다.
3. 시스템이 직원·차수·날짜·중복·기존 결과를 검증한다.
4. 사용자가 정상, 경고, 오류와 예상 변경 결과를 확인한다.
5. 사용자가 최종 반영을 승인한다.
6. 시스템이 수료 이력과 업로드 감사 정보를 하나의 처리 단위로 저장한다.
7. 차수 및 과정 지표를 재계산하고 처리 결과를 제공한다.

### 11.6 다음 차수 대상자 산정

1. 사용자가 과정을 선택한다.
2. 시스템이 기준일 현재 대상 조건을 충족하는 재직자를 산정한다.
3. 유효한 과정 수료자를 제외한다.
4. 남은 미수료자를 부서·직급·직무별로 제공한다.
5. 사용자가 선택한 인원을 차수 참여자로 등록하거나 CSV로 내려받는다.

## 13. 예외 및 오류 처리

- CSV에 존재하지 않는 사번이 있으면 해당 행을 오류로 표시하고 임의로 신규 직원을 생성하지 않는다.
- 사번은 일치하지만 이름이 다르면 경고로 표시하고 사번을 기준으로 매칭한다. 사용자의 확인 없이는 반영하지 않는다.
- 동일 직원·차수 행이 파일 안에 중복되면 오류로 처리한다.
- 이미 동일한 수료 결과가 있으면 `변경 없음`으로 표시한다.
- 기존 결과와 다른 값이 들어오면 변경 전후를 보여주고 권한과 변경 사유를 요구한다.
- 마감 또는 취소된 차수에는 강사가 새 결과를 업로드할 수 없다.
- 현재 부서 이력이 없는 재직자는 과정 대상자 계산에서 누락시키지 않고 `조직정보 오류` 목록에 포함한다. 부서 조건이 없는 과정에는 대상이 될 수 있다.
- 대상 조건을 설정하지 않은 과정은 자동으로 전 직원 대상이 되지 않는다. `대상 조건 미설정` 상태로 표시하고 수료율 산출을 중지한다.
- 과정 수료 유효기간이 만료된 직원은 현재 수료자에서 제외하되 과거 수료 이력과 만료 사실을 표시한다.
- 권한이 없는 데이터 접근은 차단하고 보안 로그에 남긴다.
- 집계 실패 시 마지막 성공 집계 시각을 표시하고 오래된 수치를 최신 값처럼 보여주지 않는다.

## 14. 비기능 요구사항

### 14.1 성능

- 일반 목록 및 대시보드의 첫 데이터 응답은 정상 네트워크 환경에서 3초 이내를 목표로 한다.
- 직원 10,000명, 과정 1,000개, 차수 10,000개, 수료 이력 1,000,000건까지 주요 조회와 집계가 가능하도록 설계한다.
- 최대 20,000행 CSV의 검증 결과를 60초 이내에 제공하는 것을 목표로 한다.
- 시간이 오래 걸리는 내보내기와 대량 집계는 백그라운드 작업으로 처리하고 진행 상태를 제공한다.

### 14.2 보안과 개인정보

- 전송 구간과 저장 데이터는 회사 보안 정책에 맞게 암호화한다.
- 권한 검사는 화면뿐 아니라 서버 및 데이터 접근 계층에서 수행한다.
- 생년월일 등 목적에 불필요한 개인정보는 수집하지 않는다.
- 로그에 인증정보, 전체 CSV 원문 또는 불필요한 개인정보를 남기지 않는다.
- 퇴사자의 보존 기간과 파기 절차는 회사 개인정보 및 인사 기록 정책을 따른다.
- 관리자 권한 부여·변경·회수는 감사 대상이다.

### 14.3 신뢰성과 데이터 품질

- 대량 반영은 트랜잭션으로 처리해 일부 저장으로 인한 불일치를 방지한다.
- 일별 백업과 복구 절차를 마련하고 운영 전 복구 시험을 수행한다.
- 주요 집계는 동일한 입력과 기준일에 대해 항상 동일한 결과를 반환해야 한다.
- 대상 조건, 집계 산식 및 데이터 정정 이력을 추적할 수 있어야 한다.

### 14.4 사용성 및 접근성

- 업무 용어와 날짜 표기를 전 화면에서 일관되게 사용한다.
- 색상만으로 수료·미수료·오류 상태를 구분하지 않는다.
- 키보드 탐색, 명확한 레이블, 충분한 색상 대비 등 WCAG 2.1 AA 수준을 목표로 한다.
- 표는 정렬, 필터, 페이지 이동과 현재 적용 조건 표시를 제공한다.
- 모바일에서는 개인 조회와 간단한 현황 확인을 지원하고, 대량 편집과 CSV 작업은 데스크톱을 기본으로 한다.

### 14.5 호환성

- 회사 표준 데스크톱 브라우저의 최신 두 개 주요 버전을 지원한다.
- CSV는 UTF-8 with BOM과 표준 쉼표 구분 형식을 기본으로 지원한다.

## 16. 1차 출시 인수 기준

1. HR이 신규 직원 등록, 부서 이동, 퇴사 처리를 수행하면 현재 직원 목록과 과거 이력이 규칙대로 반영된다.
2. 운영자가 과정과 대상 조건을 설정하면 기준일 현재 대상자 명단을 미리 확인할 수 있다.
3. 과정 대상자 중 유효한 수료 이력이 있는 직원만 수료자로 계산되고 퇴사자는 기본 현재 집계에서 제외된다.
4. 과정 상세에서 전체 및 부서별 수료자·미수료자 수, 명단과 수료율이 동일한 기준으로 표시된다.
5. 동일 과정의 여러 차수가 존재해도 과정 누적 수료자는 직원별로 중복 계산되지 않는다.
6. 강사가 정상 CSV를 업로드하면 지정한 차수에 수료 결과가 반영되고 과정 누적 현황도 갱신된다.
7. 오류가 포함된 CSV는 오류 행과 사유를 명확히 보여주며 사용자의 확인 없이 원본 데이터가 변경되지 않는다.
8. 직원 이름 또는 사번 검색으로 개인의 교육 수료 이력과 부서 근무 이력을 한 화면에서 확인할 수 있다.
9. 역할별 사용자가 허용된 범위 밖의 직원·조직·과정 정보를 조회하거나 수정할 수 없다.
10. 수료 이력 정정, 권한 변경, 직원 상태 변경과 CSV 반영 내역을 감사 로그에서 확인할 수 있다.
11. 과정별·부서별·차수별 리포트와 명단을 기준일 및 필터 정보가 포함된 CSV로 내려받을 수 있다.
12. 대상자가 없는 과정과 대상 조건이 없는 과정은 서로 다른 상태로 명확하게 표시된다.

## 18. 기존 샘플 시스템 대비 주요 변경점

| 영역 | 기존 샘플 | 개편 방향 |
|---|---|---|
| 사용자 인증 | 인증·권한 없음 | 역할 및 담당 범위 기반 접근 통제 |
| 직원 상태 | 재직·퇴사·신입 | 재직·휴직·퇴사, 신규 여부는 입사일로 판정 |
| 조직 정보 | 직원 현재 팀과 단순 이동 이력 | 부서 기준정보와 기간이 겹치지 않는 근무 이력 |
| 교육 구조 | 과정에 대상자와 수료자를 직접 연결 | 과정과 차수를 분리하고 차수별 참여·수료 관리 |
| 수료율 | 수동 지정한 과정 대상자 기준 | 과정 대상 조건에 해당하는 현재 재직자 기준 |
| 수료 명단 입력 | 화면에서 개별 처리 | CSV 사전 검증, 미리보기, 일괄 반영 및 감사 |
| 다음 차수 후보 | 과정별 수동 대상자 | 현재 대상 조건을 충족하는 미수료자 자동 산정 |
| 개인 조회 | 교육·부서·자격증·수상 혼합 | 교육 및 부서 이력 중심, 역량 태그 연결 |
| 경력 활용 | 수료 여부 중심 검색 | 역량 태그 기반 조건 검색, 숙련도와 명확히 구분 |
| 리포트 | 현재 팀 기준 단순 CSV | 기준일·필터·산식이 명시된 과정·부서·차수 리포트 |
| 변경 추적 | 제한적 | 주요 원본 데이터와 내보내기의 감사 로그 |

## 19. 전제와 정책 결정

이 PRD는 다음 전제를 적용한다.

1. 1차 직원 기준정보는 HR 또는 시스템 관리자가 관리하며, HR 시스템 자동 연동은 단계 2에서 검토한다.
2. 직원의 고유 식별자는 변경되지 않는 사번이다.
3. 기본 과정 수료율은 과정 대상 조건에 해당하는 현재 재직자를 분모로 한다.
4. 교육 차수 참여 여부와 과정 대상 여부는 서로 다른 개념으로 관리한다.
5. 교육 수료는 숙련도나 업무 적합성을 단독으로 증명하지 않는다.
6. 과정 수료 유효기간은 과정별로 설정할 수 있고 미설정 시 무기한이다.
7. 개인정보 보존 기간, 회사 인증 방식과 세부 조직 조회 범위는 회사의 기존 보안·인사 정책을 적용한다.
8. 시스템의 모든 날짜·시간은 Asia/Seoul 시간대를 기준으로 저장·표시하며, 데이터베이스에는 표준 시간 정보를 함께 보존한다.

## 20. 출시 전 필수 운영 준비사항

개발 완료만으로 운영을 시작하지 않는다. 다음 항목이 준비되어야 1차 출시할 수 있다.

- 직원·부서 기준정보의 소유 부서 및 정정 담당자 지정
- 과정별 대상 조건 승인 책임자 지정
- 수료 결과 제출 표준 CSV와 강사 안내서 배포
- 데이터 오류, 이의 제기 및 수료 정정 절차 수립
- 역할 부여와 회수 절차 수립
- 개인정보 보존·파기 및 내보내기 통제 정책 확인
- 기존 데이터 이관 결과에 대한 HR·교육 담당자의 표본 검증
- 백업 복구, 권한 우회, 대량 업로드에 대한 운영 전 시험
