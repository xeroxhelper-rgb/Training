# 직원 조직 관리 기능 설계

## 목표

직원·조직 메뉴를 Supabase 기반의 실제 관리 화면으로 전환한다. 사용자는 직원 목록을 검색·필터링하고, 신규 직원을 등록하며, 직원 상세 정보에서 필요한 필드를 수정할 수 있어야 한다.

## 범위

- 직원 목록의 이름/사번 검색
- 부서 및 재직 상태 필터
- 신규 직원 등록
- 직원 상세 정보 조회 및 편집
- 변경된 필드만 업데이트
- 직원 insert/update를 위한 RLS 정책 및 권한 부여

## 데이터 매핑

`public.employees`의 기존 필드를 사용한다.

| 화면 필드 | DB 필드 |
| --- | --- |
| 이름 | `name` |
| 사번 | `employee_number` |
| 입사일 | `hire_date` |
| 직급/직무 | `position` |
| 부서 | `svc_team` |
| 상태 | `status` |
| 이메일 | `email` |

부서는 현재 스키마 호환성을 위해 선택한 부서명을 `svc_team`에 저장한다. 별도 `department_id` 컬럼 추가는 이번 범위에서 하지 않는다.

## 화면 및 흐름

1. `/employees`
   - URL query(`q`, `department`, `status`)를 기준으로 서버 조회
   - 필터 적용 후에도 URL에 조건을 유지
   - 신규 직원 등록 버튼은 `/employees/new`로 이동

2. `/employees/new`
   - 필수값 검증: 이름, 사번, 입사일, 부서, 상태
   - 사번 중복 오류를 사용자 메시지로 표시
   - 등록 성공 시 `/employees`로 이동

3. `/employees/[id]`
   - 데모 데이터 대신 Supabase에서 직원과 관련 이력을 조회
   - 기본 화면은 읽기 모드, 편집 폼에서 필드 수정
   - 기존 값과 달라진 필드만 `update`
   - 저장 성공 시 상세 화면으로 이동

## 서버 및 보안

- 직원 조회/부서 조회는 기존 인증 사용자 정책을 사용한다.
- `system_admin`, `hr`, `manager` 역할에 직원 `insert`, `update` 권한을 부여한다.
- 서버 액션에서 인증 사용자 확인과 입력 검증을 수행한다.
- 클라이언트에서 전달된 직원 ID와 허용 필드를 서버에서 다시 제한한다.

## 검증

- 검색어, 부서, 상태 각각과 조합 필터가 올바른 행만 반환하는지 확인
- 신규 직원 등록 및 중복 사번 오류 확인
- 변경 없는 저장 시 update가 호출되지 않는지 확인
- 일부 필드 수정 시 해당 필드만 저장되는지 확인
- 직원 권한이 없는 사용자의 insert/update가 거부되는지 확인
- 전체 테스트, lint, typecheck, production build 실행
